forge-local-ai-kit v0.1.1

Where local intelligence is shaped into tools.

Forge sends a prompt to an Ollama runtime on a machine you already control and hands back a typed result with real execution evidence. One small interface, zero production dependencies, nothing leaves your network.

$ npm i forge-local-ai-kit
Read the source
ask.mjs 
import { createForge } from 'forge-local-ai-kit';

const forge = createForge({
  provider: 'ollama',
  host: process.env.OLLAMA_HOST,
  model: 'qwen3.5:9b',
});

const result = await forge.ask(
  'Name three risks in this plan.'
);

console.log(result.output);
console.log(result.metrics.clientLatencyMs);

The shop floor

Four parts, one direction of travel.
01 Your app TypeScript or ESM, Node 22+
02
Forge The smithy — shapes, measures, marks
03 Ollama Over your LAN, plain HTTP
04 Local model A machine you own

Forge does not own the fire. The runtime and the model are yours and stay yours; Forge is the hands, the tongs, and the mark on the finished piece.

What leaves the shop

A small kit that makes few things, and makes them the same way every time.

One edge, held

The library and the forge CLI run the same configuration, inference, result, and error path. There is no second implementation to drift.

Measured, not guessed

Every result carries provider, model, client latency, and whatever token and timing evidence the runtime reported. Failures carry a category, not a stack trace.

Nothing you did not ask for

Zero production dependencies. No registry, no plugin system, no agent framework. Your host never leaves your .env.

Every tool bears the mark.

A smith stamps finished work so you know the shop it came from and what it is made of. Forge does the same: the mark sits beside anything that has actually been verified, and nowhere else.

If a number on this page carries the hallmark, it was produced by a run, not a claim.
