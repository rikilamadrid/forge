# Complete Evidence and Live Verification

## Status

Proposed

## Parent Feature

`01-remote-local-inference.md`

## Blocked by

- `01.1` — working CLI-to-Ollama/Qwen delegation path

## Goal

Complete Forge's structured evidence and failure contracts, then verify Feature 01 through a real LAN delegation that returns a useful Qwen response and trustworthy metrics in both human-readable and JSON modes.

## Context

- Read: `context/features/01-remote-local-inference.md`, the implementation delivered by ticket `01.1`, the Quality Priorities in `context/project-overview.md`, the Forge TypeScript Conventions and Verification sections in `context/coding-standards.md`, and Ollama's non-streaming generate-response and error contracts.
- Relevant area: `README.md`, `src/cli.ts`, `src/ask.ts`, `src/inference.ts`, `src/providers/ollama.ts`, and focused tests under `test/`.

## Changes

- Extend the provider-neutral structured success result only as Feature 01 requires: success, provider, reported model, response text, client latency, prompt tokens, completion tokens, total tokens, and available normalized provider timings.
- Keep Ollama wire types and nanosecond duration fields inside the adapter. Expose documented millisecond values, derive total tokens only from supplied component counts, and never fabricate missing metrics as zero.
- Add `forge ask "<prompt>" --json` so standard output contains exactly one valid machine-readable JSON result; keep the default human presentation concise while exposing response and useful evidence.
- Complete stable structured failure categories for invalid configuration, network refusal, timeout, non-success HTTP, invalid Ollama responses, and provider-reported failures. Return a non-zero CLI status and no stack trace by default.
- Add deterministic tests for metric mapping and normalization, absent optional metrics, derived totals, JSON output, human output, exit statuses, and every required failure category.
- Document CLI usage, safe configuration, output modes, timeout behavior, and an explicit opt-in live verification procedure without embedding a private host, model installation instructions, or private prompt content.
- Perform the final live Feature verification against the existing Ollama/Qwen runtime on the M1 without modifying it, and capture a sanitized review record containing the path exercised, provider, reported model, success, elapsed time, and available token counts.

## Verification

- Run `npm test`, `npm run check`, and `npm run build`; all pass without access to the live Ollama machine and cover the Feature's success, parsing, metric, CLI, and error contracts.
- Supply private configuration only through the local environment, run the documented human-readable command with a non-sensitive coding task, and confirm a usable Qwen response with provider/model, latency, and token evidence.
- Run the same live task with `--json`, parse its standard output as JSON, and confirm it reports success, provider, the model reported by Ollama, response text, client latency, prompt/completion/total tokens where supplied, and every available normalized provider timing.
- Confirm the evidence demonstrates development machine → Forge → LAN → Ollama on the M1 → Qwen → Forge, and inspect tracked files plus the captured record for private hosts, private prompt text, credentials, personal information, Lorekeeper data, or LAMA-specific configuration.

## Out of Scope

- Any second provider; provider registry, factory, plugin, capability negotiation, or lifecycle machinery; streaming; persistence; benchmarking; Ollama/model management; M1 configuration changes; CI, publishing, or release work.

## Notes / Decisions

- This ticket is the final Feature 01 verification ticket. It must report unavailable metrics as unavailable rather than treating their absence as a failed call or inventing values.
- The sanitized live evidence belongs in the ticket review/completion record; do not create a benchmarking subsystem or commit raw private terminal output.
