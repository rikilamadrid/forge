# Delegate One Prompt to Qwen

## Status

Complete

## Parent Feature

`01-remote-local-inference.md`

## Blocked by

None

## Goal

Deliver the thinnest working Forge path that accepts one prompt on the development machine, sends it to the configured Ollama/Qwen runtime over the LAN, and prints a usable response with basic execution identity and latency.

## Context

- Read: `context/features/01-remote-local-inference.md`, the System, Technology, Commands, and Environments sections of `context/project-overview.md`, the Forge TypeScript Conventions in `context/coding-standards.md`, and Ollama's non-streaming generate-response contract.
- Relevant area: `package.json`, `tsconfig.json`, `.env.example`, `src/cli.ts`, `src/ask.ts`, `src/config.ts`, `src/inference.ts`, `src/providers/ollama.ts`, and focused tests under `test/`.

## Changes

- Create the minimal npm/TypeScript/ESM package and scripts needed to build, type-check, test, and invoke the `forge` CLI on Node.js 22+; TypeScript is the only initial development dependency and production dependencies remain empty.
- Implement `forge ask "<prompt>"` with prompt validation and human-readable output.
- Read and validate `OLLAMA_HOST` and `FORGE_MODEL` before network activity. Use no localhost default and commit no real machine value.
- Define an `InferenceProvider` with exactly one asynchronous generation operation and only the request/result fields this ticket consumes. Add no registry, factory, plugin, capability, or lifecycle abstraction.
- Implement one Ollama adapter that uses native `fetch` to call non-streaming generation with the configured host, model, and prompt. Do not perform model discovery or mutate the Ollama installation.
- Route the CLI through a provider-neutral ask use case. Return and present the response text, provider identity, model reported by Ollama, and client-observed latency.
- Apply a finite, documented request timeout and validate the minimum Ollama success payload needed for safe output.
- Add deterministic `node:test` coverage for configuration validation, request construction, minimal response parsing, the ask path, and basic CLI success/failure behavior using controlled HTTP and time inputs.
- Keep prompts and responses ephemeral; do not add diagnostic logging, persistence, or telemetry.

## Verification

- Run `npm test`, `npm run check`, and `npm run build`; all pass without access to the live Ollama machine.
- With private `OLLAMA_HOST` and `FORGE_MODEL` values supplied only in the local environment, invoke `forge ask` with a non-sensitive coding prompt and observe a usable response plus provider, reported model, and client latency from the existing Qwen model on the M1.
- Confirm the invocation crosses the LAN from the development machine and that no repository file or captured output contains the private host or private prompt text.

## Out of Scope

- `--json`, complete Ollama token/timing normalization, the full structured error taxonomy, final Feature acceptance evidence, or any second provider.

## Notes / Decisions

- This ticket intentionally places minimum package setup, CLI, use case, provider contract, adapter, tests, and one live call in the same vertical slice; none is an independently useful infrastructure deliverable.
- The live call proves early viability but does not complete Feature 01; ticket `01.2` completes the evidence and failure contracts.
